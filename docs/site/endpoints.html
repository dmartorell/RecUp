Backend · API

Endpoints disponibles

Endpoints expuestos por el backend Express de RecUp. Todos devuelven JSON. Los marcados como Auth requieren cabecera Authorization: Bearer <jwt>.

Renovación silenciosa de JWT

Cuando una respuesta de una ruta autenticada incluye la cabecera X-New-Token, el frontend debe sustituir el token actual por ese valor. Sucede automáticamente cuando faltan menos de JWT_RENEW_THRESHOLD_MS para que el token expire.

GET /api/auth/me Auth

Devuelve el usuario actual derivado del JWT.

Respuestas

CodeErrorMotivo
200—{ success, data: { user: { name, email, avatar } } }
401UNAUTHORIZEDToken ausente o inválido.
404NOT_FOUNDUsuario eliminado mientras el token seguía vivo.

Dónde se usa

Hoy lo consume solo el SaaS, en src/js/app.js → handlePostMessage(). Se llama una única vez: justo cuando el SaaS recibe la sesión enviada por la extensión vía postMessage de tipo recup:extension-data.

Para qué se usa

La extensión solo envía token, email y name — no envía avatar. Tras guardar esa sesión mínima en localStorage, el SaaS dispara /api/auth/me para rehidratar el perfil canónico desde la BD (incluyendo el avatar_url resuelto contra ClickUp en su día) y completar el objeto session.user. Después se vuelve a llamar a tagSentryUser() y a showApp() con los datos ya completos.

No se usa para validar la sesión (eso ya lo hace authMiddleware en cada request) ni en el boot normal del SaaS, donde el avatar viene del login. Es estrictamente un paso de rehidratación del perfil tras el handoff de la extensión.

Incidencias

CRUD de incidencias del usuario autenticado. Todos los endpoints requieren JWT y la propiedad se verifica en cada acceso por id.

GET /api/incidents Auth

Lista paginada de incidencias del usuario actual, ordenadas por created_at DESC (más recientes primero).

Query params

ParamTipoDefaultDescripción
limit int ≥ 1 20 Número máximo de incidencias a devolver en esta página. Se aplica un Math.max(1, …), así que cualquier valor < 1 (o no numérico) se normaliza a 1. No hay tope superior en backend; el frontend usa 25.
offset int ≥ 0 0 Número de filas a saltar antes de empezar a devolver resultados. Valores negativos o no numéricos se normalizan a 0. Combinado con limit implementa paginación clásica por desplazamiento.

Respuesta

{
  "success": true,
  "data": {
    "incidents": [ /* <= limit incidencias */ ],
    "total": 137   // total absoluto del usuario, no de la página
  }
}

Cómo funciona la paginación en la app

El frontend (src/js/app.js) usa paginación incremental con botón “Cargar más”, no páginas numeradas:

  1. Al cargar el feed se llama con offset = 0 y limit = 25 (constante INCIDENTS_LIMIT).
  2. Tras recibir n incidencias se hace offset += n acumulando un cursor local.
  3. Si offset < total el frontend pinta un botón “Cargar más” al final del feed. Al pulsarlo se vuelve a llamar al endpoint con el nuevo offset y los resultados se añaden al feed actual (modo append).
  4. Cuando offset >= total el botón ya no se renderiza: no quedan más incidencias por traer.
  5. Cualquier acción que reinicia el feed (login, refresh manual, borrar todo) vuelve a poner offset = 0 y limpia el DOM.
Por qué offset y no cursor

El volumen por usuario es bajo y el orden es estable (created_at DESC + autoincrement). Offset es suficiente y mucho más simple que un cursor opaco. Si en el futuro el feed se vuelve muy activo y aparecen incidencias nuevas entre cargas (lo que podría duplicar o saltarse filas), convendría migrar a cursor basado en created_at + id.

Configuración del usuario

GET /api/settings Auth

Devuelve la configuración actual. Las API keys nunca se exponen en claro, sólo un boolean configured y un hint (últimos chars).

Respuesta

{
  "clickup_list_id": "193679011",
  "ai_provider": "anthropic",
  "clickup_api_key":  { "configured": true,  "hint": "····abcd" },
  "anthropic_api_key":{ "configured": true,  "hint": "····wxyz" },
  "openai_api_key":   { "configured": false, "hint": null }
}
PUT /api/settings Auth

Actualiza configuración. Las API keys se cifran con AES-256-GCM antes de persistir. Sólo se modifican los campos que vengan como string en el body.

Body

{
  "ai_provider": "anthropic" | "openai",
  "clickup_list_id": "...",
  "clickup_api_key": "...",
  "anthropic_api_key": "...",
  "openai_api_key": "..."
}
