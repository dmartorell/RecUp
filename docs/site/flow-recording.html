Flujos

Grabación → bug report

El flujo principal de RecUp: el usuario pulsa grabar, habla, para la grabación y en segundos obtiene un bug report estructurado con título y bullets. También soporta entrada por teclado como alternativa al micrófono.

Visión general

[Usuario pulsa REC]
        │
        ├── navigator.mediaDevices.getUserMedia()   ← solicita micrófono
        ├── MediaRecorder.start()                   ← captura audio (webm/opus)
        └── SpeechRecognition.start()               ← transcripción en tiempo real (es-ES)

[Usuario pulsa STOP]
        │
        ├── stopTranscription() → transcript (string)
        ├── stopRecording()     → audioBlob (Blob webm)
        └── createIncident(transcript, audioBlob, duration)
                │
                ├── Renderiza card en el feed (estado: "procesando")
                └── runSummarize(incident, transcript, 'audio', duration)
                        │
                        │  POST /api/summarize  { transcript }
                        ▼
                [server/routes/summarize.js]
                  └── Anthropic / OpenAI → JSON { is_bug, title, bullets, transcript }
                        │
                        ├── is_bug=false → badge neutral, sin ticket
                        └── is_bug=true  → renderiza bullets, abre modal de ticket
                                └── POST /api/incidents  (persiste en Turso)

Captura de audio

Al pulsar el botón de grabación, toggleRecording() (src/js/app.js:391) arranca tres cosas en paralelo:

Acceso al micrófono

requestMicAccess() (src/js/recorder.js:7) llama a navigator.mediaDevices.getUserMedia({ audio: true }). El stream se reutiliza entre grabaciones: solo se pide permiso la primera vez. Si el usuario deniega el acceso, se muestra un toast con el mensaje de error.

MediaRecorder

startRecording() (src/js/recorder.js:26) crea un MediaRecorder con audio/webm;codecs=opus (fallback a audio/webm si el codec no está disponible). Los chunks de audio se acumulan en un array; al parar, se construye un Blob con el MIME type del recorder.

Web Speech API (transcripción)

startTranscription() (src/js/transcriber.js:59) crea un SpeechRecognition con:

  • continuous = true — no para al detectar silencio.
  • interimResults = false — solo resultados finales, reduce ruido.
  • lang = 'es-ES'

La API nativa tiene un límite de sesión (~60 s en Chrome). Para evitar cortes, cuando onend se dispara con isActive = true, el transcriber reinicia automáticamente el recognition tras 300 ms.

Los errores no-speech y aborted se ignoran (son esperables). Los errores fatales (not-allowed, network, etc.) llaman al callback de error y fuerzan un forceCleanup().

Visualizador de onda

Un AnalyserNode conectado al stream calcula el pico de amplitud por frame y ajusta la altura de las barras del waveform en el DOM. Corre con requestAnimationFrame durante la grabación.

Timeout automático

Tras 5 minutos (RECORDING_TIMEOUT_MS = 5 * 60 * 1000, src/js/app.js:257), se dispara forceCleanup() y se muestra un toast. Evita que una grabación olvidada consuma recursos indefinidamente.

Modo texto

El botón de toggle (modeToggleBtn) alterna entre modo micrófono y modo teclado. La preferencia se persiste en localStorage bajo la clave recup_input_mode.

En modo teclado, el usuario escribe en un textarea (mínimo 4 caracteres). Al pulsar «Enviar»: 

// src/js/app.js:349
createIncident(text, null, 0);

El audioBlob es null y la duración es 0. Internamente, source_type se fija a 'text' en lugar de 'audio'.

createIncident — renderizado inmediato

createIncident(transcript, audioBlob, duration) (src/js/incident-renderer.js:226) crea el card en el DOM antes de llamar a la IA, con estado «procesando» y un spinner. El usuario ve feedback instantáneo.

  • Si transcript está vacío (no se detectó voz): muestra el card sin llamar a summarize.
  • Si hay audioBlob: guarda la URL del objeto en data-audio-blob-url para el modal de ticket.
  • El card se inserta al principio del feed (feed.prepend(incident)).

Llamada a /api/summarize

runSummarize() (src/js/incident-renderer.js:130) llama a summarize(rawText) que hace: 

POST /api/summarize
Authorization: Bearer <token>
Content-Type: application/json

{ "transcript": "el usuario vio que al hacer clic en..." }

El servidor responde con JSON estricto (sin markdown). Ver detalles del backend en Integración IA (summarize).

Procesamiento del resultado

Si is_bug = false

El badge cambia a «completado» (neutro). Se muestra un mensaje «No se detectó un bug» y no aparece el botón de ticket. La transcripción se guarda en BD con status = 'completado'.

Si is_bug = true

  1. Se renderizan los bullets como lista en el card.
  2. Los datos del resumen (title, bullets, transcript) se guardan en atributos data-* del elemento DOM para que el modal de ticket los lea sin un fetch adicional.
  3. Se añade el footer con el botón «Crear ticket».
  4. El modal de ticket se abre automáticamente.
  5. saveIncidentResult() persiste el incidente en Turso: primero intenta un PATCH si ya tiene ID, si no hace un POST /api/incidents.

Si la llamada falla

El badge cambia a «error» y aparece un botón «Reintentar» que vuelve a llamar a runSummarize() con los mismos parámetros. El incidente queda en el feed sin persistir hasta que el reintento tenga éxito.

Persistencia en Turso

El incidente se persiste en dos momentos:

  • POST /api/incidents — crea la fila con status = 'completado', transcript, title, bullets (JSON string), source_type y duration_ms.
  • PATCH /api/incidents/:id — actualiza si ya existe (p.ej. al crear el ticket de ClickUp, añade clickup_task_id y clickup_task_url).
