Integración IA (summarize)

Cómo RecUp toma una transcripción, descifra la API key del usuario on-demand, enruta la llamada a Anthropic o OpenAI y normaliza la respuesta JSON antes de devolverla al frontend.

Visión general

[Frontend: POST /api/summarize  { transcript }]
        │  Authorization: Bearer <JWT>
        ▼
[authMiddleware]
        │
        ▼
[server/routes/summarize.js]
  ├── Valida transcript (string no vacío)
  ├── getUserSettings(userId)          ← SELECT + decrypt on-demand
  │     └── AES-256-GCM decrypt(anthropic_api_key | openai_api_key)
  ├── AbortController → setTimeout(30 000 ms)
  └── fetch() al proveedor configurado
        ├── 'openai'     → api.openai.com/v1/chat/completions
        │                  model: gpt-4o-mini · max_tokens: 1024 · temp: 0.3
        └── 'anthropic'  → api.anthropic.com/v1/messages
                           model: claude-haiku-4-5-20251001 · max_tokens: 1024 · temp: 0.3
              │
              ▼
        rawText → strip markdown → JSON.parse()
              │
              ▼
{ is_bug, title, transcript, bullets }

Configuración de proveedor

Cada usuario tiene una columna ai_provider en Turso ('anthropic' por defecto). El usuario la cambia desde Ajustes → el frontend llama a POST /api/settings (server/routes/settings.js), que persiste la elección y la API key correspondiente cifrada.

En server/routes/summarize.js:33, el proveedor se lee así: 

const settings = await getUserSettings(req.user.id);
const provider = settings.ai_provider || 'anthropic';

Si el usuario no ha guardado la API key del proveedor elegido, apiKey es null y el endpoint devuelve 400 SETTINGS_NOT_CONFIGURED antes de hacer ninguna llamada externa.

Descifrado on-demand de la API key

Las API keys nunca se almacenan en claro en Turso. Se guardan con el prefijo enc:v1: (AES-256-GCM) y se descifran únicamente en el momento de usarlas. La función getUserSettings (server/db.js:83) hace un SELECT + decrypt() justo antes de pasar la key al fetch: 

// server/db.js:90
return {
  ...row,
  anthropic_api_key: decrypt(row.anthropic_api_key),
  openai_api_key:    decrypt(row.openai_api_key),
};

La key descifrada existe únicamente en memoria durante el tiempo de vida del request. Si alguien vuelca la base de datos, obtiene los valores cifrados, no las keys reales.

Ver más sobre el cifrado

El esquema AES-256-GCM, el prefijo enc:v1: y qué pasa si se pierde CRYPTO_SECRET están detallados en Cifrado de API keys en reposo.

System prompt

El prompt se carga una vez al arrancar el módulo desde server/config/prompts/summarize-system.txt (server/routes/summarize.js:19) con readFileSync. No se recarga en caliente: un cambio en el archivo requiere reiniciar el servidor.

El prompt instruye al modelo a devolver únicamente JSON válido, sin markdown. Define dos formatos posibles según is_bug: 

// is_bug: true
{ "is_bug": true, "title": "…", "transcript": "…", "bullets": ["…", "…"] }

// is_bug: false
{ "is_bug": false, "transcript": "…" }

Los bullets deben ser solo hechos extraídos de la transcripción — sin hipótesis ni sugerencias de solución. El prompt incluye ejemplos de qué es correcto e incorrecto.

Routing Anthropic vs OpenAI

Las diferencias entre las dos llamadas son estructurales (formato de la API) pero los parámetros de generación son idénticos:

Parámetro Anthropic OpenAI
Endpoint /v1/messages /v1/chat/completions
Auth header x-api-key: <key> Authorization: Bearer <key>
Modelo claude-haiku-4-5-20251001 gpt-4o-mini
max_tokens 1024 1024
temperature 0.3 0.3
System prompt Campo system top-level Mensaje { role: 'system', … }

Todas las constantes viven en server/config/constants.js, no inline en el router.

Timeout y AbortController

Antes del fetch, se crea un AbortController y se arma un setTimeout de 30 segundos (SUMMARIZE_TIMEOUT_MS): 

const controller = new AbortController();
const timeout = setTimeout(() => controller.abort(), SUMMARIZE_TIMEOUT_MS);

// … fetch con signal: controller.signal …

clearTimeout(timeout); // limpieza si el fetch termina antes

Si la llamada supera los 30 s, el fetch lanza un AbortError, que el bloque catch intercepta y devuelve como 504 TIMEOUT. No hay retry automático: si Anthropic u OpenAI se caen, el request se pierde.

Límite sin retry

Un timeout sin reintentos es un bottleneck en producción. Si el proveedor sufre latencia alta, el usuario recibe un error en lugar de esperar. Contexto más amplio en Escalabilidad — timeouts IA.

Parseo y normalización de la respuesta

Aunque el prompt pide JSON sin markdown, los modelos a veces envuelven la respuesta en un bloque ```json … ```. El código lo limpia antes de parsear: 

const cleaned = rawText
  .replace(/^```(?:json)?\s*\n?/i, '')
  .replace(/\n?```\s*$/, '')
  .trim();
parsed = JSON.parse(cleaned);

Si JSON.parse falla, el endpoint devuelve 502 INVALID_JSON. Si el cuerpo de la API externa es vacío o mal formado, devuelve 502 EMPTY_RESPONSE.

La respuesta final siempre incluye los cuatro campos (con valores por defecto para los opcionales): 

return res.json({
  is_bug:     parsed.is_bug ?? false,
  title:      parsed.title || null,
  transcript: parsed.transcript,
  bullets:    parsed.bullets || [],
});

Errores posibles

Código HTTP Error Causa
400 TRANSCRIPT_REQUIRED transcript ausente o solo espacios
400 SETTINGS_NOT_CONFIGURED El usuario no tiene API key del proveedor elegido
401 — JWT inválido o expirado (lo devuelve authMiddleware)
502 AI_API_ERROR La API externa devolvió un status no-2xx
502 EMPTY_RESPONSE La respuesta del modelo no contenía texto
502 INVALID_JSON El modelo devolvió texto que no es JSON parseable
504 TIMEOUT La llamada superó 30 s
